# Document commitments

A Pool's immutable `agreement_hash` commits to the exact rules document. IPO
Cases also commit to a canonical result generated by Manteon from typed facts.
The contract stores commitments and event facts; document storage and readable
agreement formatting belong to integrating applications.

```text
agreement_hash = SHA-256(exact agreement bytes)
result_hash = SHA-256(UTF-8(Manteon canonical result))
```

## Agreement boundary

`create_pool` requires a nonzero agreement hash and validates its separately
supplied event, algorithm, schedule and reviewed Config hash. It receives no
agreement document, parses no prose and cannot compare the text with those
fields. Applications must verify that the document they present accurately
describes Pool/Event settings, evidence sources and review semantics.

No instruction edits a Pool's agreement hash, schedule, algorithm or Event
definition. Display metadata or archive edits cannot change those terms. New
terms require a new Pool. Equal document bytes have equal hashes; Pool addresses
and Case nonces distinguish independent pools and review attempts.

## Canonical result

The [result formatter](../programs/manteon/src/result.rs) and
[event-owned facts](../programs/manteon/src/state/event/document.rs) define the
exact Version 1 Markdown. It uses UTF-8, LF line endings, a final newline,
canonical base58 addresses, lowercase hexadecimal hashes and UTC timestamps
`YYYY-MM-DDTHH:MM:SSZ`, bounded from 1970 through 9999. Its IPO envelope is:

```text
# Manteon event result

Version: 1

## Reported event

- Event: company_ipo
- Token mint: <mint>
- Occurred at: <UTC timestamp>

## Agreement and pool

- Program: <Manteon program>
- Pool: <Pool address>
- Agreement hash: <64 lowercase hex characters>
```

Price results use `token_price_threshold_crossing` and insert the complete fixed
price rule and verified lower/upper USD bounds after the mint. The source
formatter defines field order. Price results live directly in Event and do not
create a Tekmerion Case or store a separate result-hash field; their canonical
document hash can be derived from these recorded facts.

For an IPO proposal, callers supply validated occurrence facts, not an arbitrary
result hash. Manteon renders and hashes them before Tekmerion CPI. Acceptance
authenticates the current Case's policy, subject, sequence, agreement hash and
derived result hash. A historical result must be verified against its own
historical Case, because Event may contain a later candidate.

## Independent verification

1. Read authentic program-owned Pool/Event accounts on the intended network.
   For IPO results, authenticate the relevant Tekmerion Case as well.
2. Obtain the original document and hash its exact bytes. Do not trim, convert
   newlines, normalize Unicode or hash a rendered PDF instead of its original.
3. Compare the hash to the chain commitment and compare its structured facts
   with Pool/Event identity, schedule, algorithm and event parameters.
4. Review external evidence under the committed event rules. Document integrity
   establishes byte identity, not factual truth.

A URL commitment fixes its string, not future page contents. Source snapshots
are off-chain evidence unless explicitly committed by an application. Publishing
a document creates no Pool, Case or authorized signature. Archive availability,
issuer identity, token rights, RPC provenance and program upgrades remain
separate concerns. Eligible withdrawal, exit and claim transactions do not
require an archive or agreement text.
